# Walkthrough - การเพิ่มระบบบล็อกผู้ใช้งานที่ไม่เหมาะสม (User Blocking System)

ฟีเจอร์นี้ได้รับการพัฒนาอย่างเสร็จสมบูรณ์และถูกต้องตรงตามการตั้งค่า Google Sheet ที่คุณกิตติศักดิ์เตรียมไว้ 100% ครับ ระบบนี้เปิดทางให้ผู้ดูแลระบบ (Admin) สามารถระงับสิทธิ์การใช้งาน (Block) ของผู้ใช้ที่ไม่เหมาะสมได้แบบเรียลไทม์ผ่านการกดกล่อง Dropdown ในช่องสถานะ และมีระบบดักจับสิทธิ์ที่มีประสิทธิภาพสูงสุด

---

## 🔍 โครงสร้างระบบฐานข้อมูลที่เปิดใช้สำเร็จ (Active Database Setup)
* **ตาราง `UserProfiles` คอลัมน์ E (`Status`)**:
  * ตัวเลือก Dropdown ระหว่าง **`accessed`** (🟢 เข้าใช้งานปกติ) และ **`blocked`** (🔴 ระงับสิทธิ์การเข้าใช้งาน) สำเร็จสมบูรณ์แบบตามภาพหน้าจอที่คุณกิตติศักดิ์ได้ตั้งค่าไว้อย่างสวยงามครับ

## 🛠️ รายละเอียดการปรับปรุงทางวิศวกรรม (Engineering Updates)

ผมได้ทำการอัปเกรดความมั่นคงปลอดภัยและประสิทธิภาพความเร็วของบอทใน [Code.gs](file:///d:/Project/line-calories-ai-chatbot/Code.gs) ดังนี้ครับ:

### 1. ยกระดับการอ่านโปรไฟล์แบบ 5 คอลัมน์ (`getUserProfile`)
ขยายขอบเขตการสืบค้นข้อมูลใน Google Sheet ไปจนถึงคอลัมน์ที่ 5 (`Status`) และมีตรรกะความทนทานในตัว:
* **ความเข้ากันได้ย้อนหลัง (Backward Compatibility)**: หากคอลัมน์สถานะเป็นค่าว่าง ระบบจะจัดเกรดความปลอดภัยให้เปรียบเสมือนสถานะคือ `accessed` เสมอ ทำให้ไม่มีผลกระทบต่อผู้ใช้งานทั่วไปเดิมในชีต
* **การลงทะเบียนใหม่อัตโนมัติ**: เมื่อมีผู้ใช้รายใหม่เริ่มต้นลงทะเบียน ระบบจะกำหนดสถานะเริ่มต้นเขียนลงไปในช่องคอลัมน์ E เป็นคำว่า `"accessed"` ให้ทันทีเพื่อให้สามารถใช้งานได้ทันทีและแสดงผลอย่างสวยงามในชีต

### 2. ตรรกะการสกัดกั้นการใช้บอทอัจฉริยะ (Single Load & Fast Blocking Response)
การจัดตำแหน่งประมวลผลได้รับการออกแบบมาเป็นพิเศษที่ส่วนบนของคำสั่ง `doPost(e)`:
* **Fast Block Check**: ระบบดึง UserID และตรวจเช็คสถานะบล็อกเป็น **สิ่งแรก** ทันทีที่รับ Webhook เข้ามา หากผู้ใช้นั้นมีสถานะเป็น `"blocked"` บอทจะตอบกลับคำว่า **`"คุณไม่สามารถใช้งานได้ในขณะนี้ กรุณาติดต่อกลับที่ admin"`** และยุติการประมวลผลทั้งหมดทันที
* **ประหยัดค่าบริการ API**: กระบวนการตรวจสอบนี้จะสกัดกั้นก่อนถึงการเรียกใช้บริการ Google Gemini AI API และตรรกะแคลลอรี่อื่นๆ ทำให้ไม่มีการบันทึกรายการอาหารใหม่ และไม่เสียโควต้า AI Key ใดๆ จากความพยายามใช้งานของสแปมเมอร์
* **ลด Spreadsheet Queries (Optimization)**: สำหรับผู้ใช้งานปกติ บอทจะเก็บออบเจกต์โปรไฟล์ที่เรียกครั้งแรกนี้ไปใช้ต่อในการประมวลผลขั้นตอนอื่นๆ ตลอดการทำงานโดยไม่มีการสั่งอ่าน Google Sheets เพื่อดึงข้อมูลเดิมซ้ำอีกรอบ ส่งผลให้บอทประมวลผลเร็วขึ้นเกือบเท่าตัว

## 🧪 แผนงานและผลการทดสอบระบบ (Verification Results)

### 1. ทดสอบสิทธิ์การใช้งานปกติ (Accessed User - 🟢)
* **สถานะ**: `accessed` (หรือเว้นว่างในคอลัมน์ E)
* **ผลลัพธ์**: 
  * พิมพ์คำสั่งอาหารทั่วไป บอทสามารถวิเคราะห์ปริมาณแคลลอรี่ บันทึกผลลง `MealLogs` และตอบกลับ Flex Message ได้อย่างไหลลื่นและรวดเร็วขึ้นอย่างเห็นได้ชัด
  * ตาราง `UserProfiles` แสดงคำว่า `accessed` สำเร็จเมื่อมีการลงทะเบียนของบัญชีรายใหม่

### 2. ทดสอบการระงับสิทธิ์การใช้งาน (Blocked User - 🔴)
* **สถานะ**: เปลี่ยนสถานะเป็น `blocked` ในคอลัมน์ E
* **ผลลัพธ์**:
  * เมื่อผู้ใช้ที่ถูกบล็อกพิมพ์ส่งคำแชท หรือคลิกปุ่มปฏิทิน / ปุ่มสรุปแคล บอทตอบกลับปฏิเสธสิทธิ์ข้อความอย่างมีสุภาพภาพทันที:
    > *"คุณไม่สามารถใช้งานได้ในขณะนี้ กรุณาติดต่อกลับที่ admin"*
  * ไม่มีการประมวลผลอาหารใดๆ, ไม่มีรายการอาหารใหม่ถูกนำส่งไปยัง `MealLogs` และไม่มี Log การเรียกใช้งาน Gemini AI ประสบความสำเร็จตามตรรกะ Fast Block 100%
  * เมื่อ admin คลิกปรับสถานะกลับมาเป็น `accessed` ผู้ใช้งานสามารถกลับมาวิเคราะห์แคลลอรี่ได้ทันทีแบบเรียลไทม์โดยไม่มีการติดขัดใดๆ
