# แผนงานระบบคำนวณแคลลอรี่จำเพาะบุคคล (Personalized Calorie Limit & User Profile Onboarding)

แผนการพัฒนาระดับถัดไป (Next Step) นี้ มีเป้าหมายเพื่อยกระดับความแม่นยำในการวิเคราะห์ปริมาณแคลลอรี่และให้ข้อแนะนำทางโภชนาการจำเพาะบุคคล (Personalization) โดยการเก็บข้อมูล "เพศสภาพ" และ "วันเกิด" ของผู้ใช้งาน เพื่อนำมาประเมินค่าพลังงานสูงสุดที่แนะนำต่อวัน (Max Daily Calories) แทนการฟิกค่าคงที่ 2,000 kcal และสรุปพลังงานคงเหลือ/เกินต่อวันเพื่อให้ผู้ใช้วางแผนออกกำลังกายได้ง่ายขึ้น

---

## 🗺️ สถาปัตยกรรมระบบฐานข้อมูลและการไหลของข้อมูล (System Architecture)

### 1. โครงสร้างฐานข้อมูล Google Sheets
เราจะเพิ่มแผ่นงาน (Tab) ที่ 2 ในไฟล์ Google Sheet เดิมของคุณชื่อว่า **`UserProfiles`** เพื่อแยกการบันทึกประวัติการกินและการเก็บโปรไฟล์ของผู้ใช้ให้เป็นระบบระเบียบ

| คอลัมน์ | ชื่อฟิลด์ | ประเภทข้อมูล | คำอธิบาย |
| :--- | :--- | :--- | :--- |
| **A** | UserID | String | LINE User ID ประจำตัวผู้ใช้ (Primary Key) |
| **B** | BirthDate | String/Date | วันเดือนปีเกิดของผู้ใช้ รูปแบบ `yyyy-MM-dd` |
| **C** | Gender | String | เพศสภาพ (`ชาย` / `หญิง`) |
| **D** | RegisteredAt | String/Date | วันเวลาที่ลงทะเบียนข้อมูลโปรไฟล์สำเร็จ |

## 🤖 ระบบลงทะเบียนโปรไฟล์ด้วยกล่องข้อความโต้ตอบอัตโนมัติ (Onboarding Flow)

เมื่อผู้ใช้พิมพ์เมนูอาหารใหม่ หรือกดปุ่มขอสรุปแคลลอรี่ บอทจะทำการตรวจสอบประวัติในตาราง `UserProfiles`:
*   **กรณีที่ 1**: ค้นพบโปรไฟล์เรียบร้อยแล้ว -> ทำการวิเคราะห์แคลลอรี่/สรุปผลตามเป้าหมายของคนนั้นทันที
*   **กรณีที่ 2**: ยังไม่เคยลงทะเบียนโปรไฟล์ -> บอทจะเริ่มเข้าสู่ **โหมด Onboarding** เพื่อสอบถามข้อมูลเพศและวันเกิดด้วยระบบกล่องข้อความอัจฉริยะ (Interactive Flex Messages):

```mermaid
sequenceDiagram
    actor User as ผู้ใช้งาน LINE
    participant Bot as LINE Calorie Bot (Apps Script)
    database DB as Google Sheet

    User->>Bot: ถามแคลลอรี่เมนูอาหาร หรือ ขอสรุปประวัติ
    Bot->>DB: ตรวจสอบ UserID ในตาราง UserProfiles
    alt ไม่พบประวัติผู้ใช้ (ครั้งแรก)
        Bot->>User: ส่งกล่อง Flex Message ถามเพศสภาพ ("ชาย" / "หญิง")
        User->>Bot: คลิกเลือกเพศสภาพ (ส่งค่ากลับผ่าน Postback)
        Bot->>User: ส่งกล่อง Flex Message ถามวันเกิด (แสดงปุ่มเปิดปฏิทิน LINE Native DatePicker)
        User->>Bot: เลือกวันเกิดผ่านปฏิทิน (ส่งวันเกิดกลับผ่าน Postback)
        Bot->>DB: บันทึกข้อมูลลงตาราง UserProfiles
        Bot->>User: แจ้งเตือนยินดีต้อนรับ แสดงอายุและ Max Calories ประจำตัวสำเร็จ!
    else พบประวัติแล้ว
        Bot->>Bot: คำนวณอายุปัจจุบัน และหา Max Calories จำเพาะบุคคล
        Bot->>User: ประมวลผลและตอบกลับการ์ด Flex Message ทันที
    end
```

> [!TIP]
> **ระบบ DatePicker บน LINE (ไร้ความผิดพลาดจากการพิมพ์)**
> เพื่อให้ใช้งานได้ง่ายที่สุดและป้องกันความผิดพลาดจากการพิมพ์วันเกิดผิดรูปแบบ บอทจะใช้ปุ่ม Action ประเภท **`datetimepicker`** ของ LINE ซึ่งจะเรียกปฏิทินระบบขึ้นมาให้จิ้มเลือกวัน เดือน ปีเกิดอย่างเป็นธรรมชาติ 100%

## 📊 ตาราง Logic การคำนวณแคลลอรี่สูงสุดจำเพาะบุคคล (Max Calories Logic)

คำนวณอายุปัจจุบันของผู้ใช้งานโดยอิงจากปีปัจจุบัน ลบปีเกิด (และตรวจสอบเดือน/วันปัจจุบัน) จากนั้นกำหนดค่า `MaxCalories` อิงตามตารางโภชนาการทางการแพทย์ที่คุณกิตติศักดิ์เตรียมให้:

*   **เด็กเล็ก (อายุ 4 - 8 ปี)**: ชาย = `1,400` kcal | หญิง = `1,200` kcal
*   **เด็กโต (อายุ 9 - 13 ปี)**: ชาย = `1,800` kcal | หญิง = `1,600` kcal
*   **วัยรุ่น (อายุ 14 - 18 ปี)**: ชาย = `2,200` kcal | หญิง = `1,800` kcal
*   **วัยทำงานตอนต้น (อายุ 19 - 30 ปี)**: ชาย = `2,400` kcal | หญิง = `2,000` kcal
*   **วัยทำงานตอนกลาง (อายุ 31 - 50 ปี)**: ชาย = `2,200` kcal | หญิง = `1,800` kcal
*   **วัยผู้ใหญ่ตอนปลาย (อายุ 51 ปีขึ้นไป)**: ชาย = `2,000` kcal | หญิง = `1,600` kcal

## 🍽️ ดีไซน์การ์ดสรุปประวัติพลังงานคงเหลือ / เกินรายวัน (Today's Calorie Diff Display)

เมื่อคลิกสรุปแคลลอรี่รายวัน บอทจะวิเคราะห์พลังงานสะสมเทียบกับเป้าหมายจำเพาะบุคคล และแสดงผลการ์ด Flex Message โฉมใหม่ที่มีรายละเอียดเพิ่มดังนี้:

1.  **กรณีแคลลอรี่ยังไม่เกินเป้าหมาย (Remaining calories)**:
    *   **สไตล์**: โทนสีเขียวสดชื่น 🟢
    *   **การแสดงผล**: แสดงพลังงานที่ทานไปแล้ว (เช่น `1,200` kcal) พร้อมข้อความเด่นชัดด้านล่าง: **"ยังทานได้อีก: 800 kcal"** เพื่อให้วางแผนมื้อถัดไปได้ง่าย
2.  **กรณีแคลลอรี่ทะลุเป้าหมาย (Exceeded calories)**:
    *   **สไตล์**: โทนสีแดงแจ้งเตือน 🔴
    *   **การแสดงผล**: แสดงพลังงานที่ทานไปแล้ว (เช่น `2,400` kcal) พร้อมข้อความเตือนเด่นชัด: **"เกินเป้าหมายวันนี้ไปแล้ว: 400 kcal ⚠️"** เพื่อให้เตรียมวางแผน Burn แคลออกด้วยการออกกำลังกาย

## 🛠️ แผนการปรับปรุง Code.gs

1.  **รองรับเหตุการณ์ Postback (`doPost`)**:
    เพิ่มการแยกแยะ Event ประเภท `postback` เพื่อดึงค่าการเลือกเพศสภาพและการคลิกเลือกวันเกิดจากปฏิทิน LINE
2.  **ฟังก์ชันประเมินสิทธิ์และคำนวณสุขภาพ**:
    *   `getUserProfile(userId)`: อ่านข้อมูลโปรไฟล์จากชีต `UserProfiles`
    *   `calculateAge(birthDateStr)`: คำนวณอายุจำเพาะวันเกิด
    *   `getMaxCalories(age, gender)`: ถอดสูตร logic หาขีดจำกัดแคลลอรี่ประจำตัว
3.  **ฟังก์ชันช่วยลงทะเบียนขั้นบันได (State Management)**:
    บอทจะส่งคำถามสร้างโปรไฟล์ให้ผู้ใช้ตอบทีละข้อด้วยปุ่มกด
4.  **ปรับปรุงดีไซน์ `createSummaryFlex`**:
    คำนวณผลต่าง `MaxCalories - totalCalories` และใส่กล่องแสดงตัวเลขและคำแนะนำสุขภาพสีเขียว/สีแดงเข้าไปในการ์ดสรุปแคลลอรี่สะสม

## 📝 สิ่งที่คุณกิตติศักดิ์ต้องเตรียมพร้อม (Prerequisites)

1.  **สร้างแท็บใน Google Sheet**:
    เปิดไฟล์ Google Sheet เดิมของคุณ (`Line-ai-calories`)
2.  เพิ่มชีตแท็บที่ 2 ตั้งชื่อว่า **`UserProfiles`**
3.  พิมพ์ชื่อหัวตารางในแถวที่ 1 (คอลัมน์ A ถึง D) ดังนี้:
    *   คอลัมน์ A: `UserID`
    *   คอลัมน์ B: `BirthDate`
    *   คอลัมน์ C: `Gender`
    *   คอลัมน์ D: `RegisteredAt`

คุณกิตติศักดิ์คิดเห็นอย่างไรกับแผนงาน onboarding และดีไซน์การคำนวณแคลลอรี่ส่วนต่างจำเพาะบุคคลนี้บ้างครับ? หากมีความคิดสร้างสรรค์เพิ่มเติมหรืออนุมัติแผนนี้ สามารถแจ้งผมเพื่อเตรียมพัฒนาโค้ดระดับสูงในขั้นถัดไปได้เลยครับ!
