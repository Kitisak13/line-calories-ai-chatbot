# แผนการพัฒนาคุณสมบัติระบบบล็อกผู้ใช้งานที่ไม่เหมาะสม (User Blocking System)

ฟีเจอร์นี้มีเป้าหมายเพื่อสร้างระบบการบริหารจัดการ (Administration Control) ที่ช่วยให้ผู้ดูแลระบบ (Admin) สามารถระงับสิทธิ์การใช้งาน (Block) ของผู้ใช้บางคนที่มีพฤติกรรมการใช้งานที่ไม่เหมาะสม โดยใช้ Google Sheets ตารางประวัติเดิมเป็นตัวควบคุมสถานะอย่างยืดหยุ่นและง่ายดายที่สุด

---

## 🗺️ การออกแบบและการทำงานของระบบ (Design & Mechanism)

เราจะออกแบบระบบบล็อกโดยอิงตามความต้องการและความคุ้นเคยในการบริหารจัดการของคุณกิตติศักดิ์ ดังนี้ครับ:

### 1. การขยายโครงสร้างตารางข้อมูลใน Google Sheets (`UserProfiles`)
เราจะเพิ่มคอลัมน์ที่ 5 (คอลัมน์ E) ในแผ่นงาน **`UserProfiles`** โดยกำหนดให้เป็นคอลัมน์ **`Status`**

| คอลัมน์ (Column) | ชื่อฟิลด์ (Field Name) | ประเภทข้อมูล (Type) | คำอธิบาย (Description) |
| :---: | :--- | :--- | :--- |
| **A** | UserID | String | LINE User ID ประจำตัวผู้ใช้งาน (Primary Key) |
| **B** | BirthDate | String/Date | วันเดือนปีเกิดของผู้ใช้งาน (`yyyy-MM-dd`) |
| **C** | Gender | String | เพศสภาพ (`ชาย` / `หญิง`) |
| **D** | RegisteredAt | String/Date | วันเวลาที่เริ่มบันทึกข้อมูล |
| **E** | **Status** | String (Dropdown) | สถานะสิทธิ์การเข้าใช้งาน บังคับสองค่า: <br>• `"accessed"` (ปกติ)<br>• `"blocked"` (ระงับการเข้าใช้งาน) |

> [!TIP]
> **การเปิดใช้งาน Dropdown สะดวกต่อ Admin**
> ในฝั่ง Google Sheet คุณกิตติศักดิ์สามารถตั้งค่า **Data Validation (การตรวจสอบสิทธิ์ข้อมูล)** ในคอลัมน์ E ให้แสดงเป็นกล่องตัวเลือก (Dropdown List) ที่ปรับเปลี่ยนค่าได้ง่ายด้วยการคลิกเลือกเพียงคลิกเดียว (ระหว่าง `accessed` และ `blocked`) เพื่อระงับสิทธิ์ผู้ใช้รายบุคคลได้ทันที

### 2. หลักการทำงานที่เข้ากันได้ย้อนหลัง (100% Backward Compatibility)
เพื่อให้ผู้ใช้เดิมที่เคยลงทะเบียนไปแล้วสามารถใช้งานต่อไปได้โดยไม่ต้องสมัครใหม่:
* หากฟิลด์ **`Status` (คอลัมน์ E)** ของผู้ใช้คนใดเป็น **ค่าว่าง** หรือ **ไม่มีคอลัมน์นี้** ระบบจะประเมินให้สถานะเป็น **`"accessed"` (มีสิทธิ์เข้าใช้งาน)** โดยอัตโนมัติ ทำให้ผู้ใช้เก่าทุกคนใช้งานต่อได้ตามปกติทันที

## 🚀 ขั้นตอนการปรับปรุงคำสั่งใน `Code.gs`

เพื่อประหยัดทรัพยากรการประมวลผลและทำให้ระบบทำงานได้รวดเร็วขึ้นเป็นทวีคูณ เราจะออกแบบการโหลดและเช็คสิทธิ์แบบ **Single Load Optimization** ดังนี้ครับ:

### 1. ปรับปรุงการโหลดโปรไฟล์ (`getUserProfile`)
อัปเดตให้อ่านข้อมูลเพิ่มจากตาราง `UserProfiles` ขยายขอบเขต Range ไปจนถึงคอลัมน์ที่ 5 (คอลัมน์ E) และส่งคืนฟิลด์ `status` กลับมา:
```javascript
const data = sheet.getRange(2, 1, lastRow - 1, 5).getValues(); // ดึง UserID, BirthDate, Gender, RegisteredAt, Status
// ...
return {
  userId: String(row[0]).trim(),
  birthDate: birthDateStr,
  gender: String(row[2]).trim(),
  status: row[4] ? String(row[4]).trim() : "accessed" // ถ้าว่าง ให้เป็น accessed โดยอัตโนมัติ
};
```

### 2. ปรับปรุงการลงทะเบียนเริ่มต้น (`saveUserProfile`)
เมื่อบันทึกข้อมูลผู้ใช้รายใหม่ลงในชีต ระบบจะเขียนค่าสถานะเริ่มต้นเป็น `"accessed"` ลงไปในคอลัมน์ที่ 5 โดยอัตโนมัติ

### 3. ปรับแต่งโครงสร้าง `doPost(e)` (Single Load & Fast Blocking Response)
* **รวดเร็วและปลอดภัย**: โหลดข้อมูลโปรไฟล์ของผู้ใช้งาน (`userProfile = getUserProfile(userId)`) ตั้งแต่เริ่มรันเหตุการณ์ `doPost`
* **ดักจับทันที**: ตรวจเช็คสถานะหาก `userProfile && userProfile.status === "blocked"` บอทจะทำการส่งข้อความตอบกลับเพื่อแจ้งสิทธิ์ระงับทันที:
  > *"คุณไม่สามารถใช้งานได้ในขณะนี้ กรุณาติดต่อกลับที่ admin"*
  และบอทจะยุติการทำงาน (Abort) ทั้งหมดทันทีโดยไม่เข้าสู่การประมวลผลข้อความหรือเรียกใช้งาน AI Gemini API ซึ่งช่วย **ประหยัดค่าบริการ API Key และทรัพยากรระบบ**
* **ส่งต่อการประมวลผล (Optimization)**: สำหรับผู้ใช้งานปกติ บอทจะนำตัวแปร `userProfile` ที่โหลดไว้ตั้งแต่บรรทัดแรกไปส่งต่อใช้งานในกระบวนการข้อความปกติทันที โดยไม่ต้องสั่งอ่านแผ่นงาน Google Sheets ซ้ำอีกรอบ ส่งผลให้บอทประมวลผลเร็วขึ้นเกือบเท่าตัว!

## 📝 สิ่งที่คุณกิตติศักดิ์ต้องเตรียมตัวทำใน Google Sheet (Prerequisites)

1. เปิดไฟล์ Google Sheet ฐานข้อมูลของคุณขึ้นมา
2. ไปที่แผ่นงานชื่อ **`UserProfiles`**
3. พิมพ์หัวข้อเพิ่มเติมในแถวที่ 1 คอลัมน์ E ว่า **`Status`**
4. *(แนะนำเพิ่มเติมเพื่อความสะดวก)*:
   * เลือกคอลัมน์ E ทั้งหมด (ยกเว้นหัวตารางแถวที่ 1)
   * คลิกขวา -> เลือก **Dropdown (รายการแบบเลื่อนลง)** หรือไปที่เมนู **Data (ข้อมูล) -> Data validation (การตรวจสอบสิทธิ์ข้อมูล) -> Add rule (เพิ่มกฎ)**
   * ตั้งค่าเกณฑ์เป็น **Dropdown (รายการแบบเลื่อนลง)** และเพิ่มตัวเลือก 2 ค่าคือ:
     1. **`accessed`** (แนะนำให้ใส่สีเขียวสดใส 🟢)
     2. **`blocked`** (แนะนำให้ใส่สีแดงเตือนภัย 🔴)
   * กด **Done (เสร็จสิ้น)**

## 🧪 แผนการทดสอบระบบ (Verification Plan)

หลังอัปเดตโค้ดเรียบร้อยแล้ว เราจะตรวจสอบความถูกต้องผ่านกระบวนการจำลองดังนี้:

### การทดสอบสิทธิ์ผู้ใช้ทั่วไป (Accessed User)
1. พิมพ์บอกเมนูอาหาร หรือกดขอสรุปแคลลอรี่ตามปกติ
2. ระบบต้องสามารถคำนวณ บันทึกผล และตอบกลับด้วยดีไซน์การ์ดตามปกติ 100%

### การทดสอบระงับสิทธิ์ (Blocked User)
1. คัดลอกไอดี UserID ของคุณใน Google Sheet
2. เลือกสถานะในคอลัมน์ E ของไอดีคุณเป็น **`blocked`**
3. พิมพ์ส่งคำถามอะไรก็ได้เข้าแชทบอท
4. บอทต้องตอบกลับทันทีว่า: **`คุณไม่สามารถใช้งานได้ในขณะนี้ กรุณาติดต่อกลับที่ admin`**
5. ตรวจสอบในตาราง `MealLogs` ต้องไม่มีรายการใหม่ถูกบันทึก และไม่มี Log การเรียกใช้ Gemini API
